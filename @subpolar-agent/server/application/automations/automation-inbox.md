# Automation, Inbox, and Notifications

The bridge owns durable `automations` and `automation_runs` records. Automation input is validated before persistence, and all reads and mutations use the authenticated PocketBase owner. A trigger key is unique per owner and automation, providing idempotent manual and scheduler triggers. `executeAutomation` is the executor seam: callers inject the existing Pi/Subpolar run callback; this module does not create another agent runtime.

Runs persist attempts, lease identities, retry metadata, cancellation, and `unknown`/`interrupted` outcomes. Lease renewal, expiry, and cancellation check owner/state/lease identity. The current bridge explicitly opts into **process-local** serialization on one database client; this is not durable compare-and-set or safe multi-process worker coordination. A repository without an explicit serialization capability fails closed. Startup maintenance marks active runs `unknown`; pending/retrying records can be polled again, but active Pi execution and process-local approval payloads are not resumed. Concurrency policy is enforced at trigger time and lease acquisition for both manual and scheduled runs. Schedule consumption occurs at scheduled trigger time, never on manual completion.

`inbox_items` is the authoritative presentation store for supported domain projections. Identity includes owner, optional project, kind, and reference. Automation success/review/failure/cancellation/interruption and task review/terminal transitions project items; not all approval/question sources are wired into the inbox. Browser clients cannot synthesize or overwrite projections. Resolve acknowledges an item; it does not grant underlying tool approval. Notification subscriptions and delivery rows are projections only; adapter failures preserve the inbox item. Retryable failures persist pending delivery metadata, but recovery requires a durable serialization capability not currently supplied by the bridge.

`triggerDue(ownerId)` is the scheduler trigger seam: it finds active due definitions and creates idempotent schedule runs. The bridge polls this seam every ten seconds. Cron is five-field, range-checked, and next-run calculation is bounded to a one-year horizon. Clock-aligned representable intervals translate to cron; unsupported intervals fail rather than being silently rescheduled. This is not arbitrary elapsed-time interval scheduling.

Routes are owner-scoped under `/api/automations`, `/api/inbox`, and `/api/notifications`. Owner identity always comes from authentication. See `docs/progress-automations-inbox.md` for validation and remaining runtime, delivery, and UI blockers.
