# @subpolar/browser

Portable Playwright Chromium engine and authenticated internal worker. No application or database imports. Each session gets a separate Chromium process; persistent contexts use exclusive filesystem profile leases. The application must authorize every session, profile and action before invoking this port. The worker token is an administrator secret, never supplied to browsers or agents.

Run `bun install`, `bunx playwright install --with-deps chromium`, then `SUBPOLAR_BROWSER_WORKER_TOKEN=<32+ random characters> bun packages/subpolar-browser/src/worker.ts`. Linux must run as a nonroot account with a kernel/container configuration supporting the Chromium sandbox. The package never disables Chromium's sandbox.

Configuration: `SUBPOLAR_BROWSER_WORKER_HOST` (127.0.0.1), `SUBPOLAR_BROWSER_WORKER_PORT` (3101), `SUBPOLAR_BROWSER_PROFILE_ROOT` (./browser-profiles), `SUBPOLAR_BROWSER_MAX_SESSIONS` (4), `SUBPOLAR_BROWSER_IDLE_MS` (900000), `SUBPOLAR_BROWSER_ALLOWED_PRIVATE_HOSTS` (empty). Private-host exceptions are comma-separated exact trusted administrator hostnames, never agent-provided. Keep worker port internal; use HTTPS or a trusted private network between app and worker.

`WorkerBrowserPort(url, token)` implements the existing browser port plus `start(sessionId,{profileId?,limits?})`, `action(sessionId,operation,input,tabId?)`, `clearProfile(profileId)` and `health()`. `startBrowserWorker(options)` returns `{server,engine,close}` for hosting/tests. `ChromiumBrowserPort(options)` runs the same engine locally and offers `dispose()` for shutdown.

Actions include snapshot, click, double-click, hover, scroll, fill, type, press, select-option, check, uncheck, drag, upload, select-tab, close-tab, reload, resize, pointer and keyboard. Semantic locators use `{locator:{role,name}}`, `{locator:{label}}` or `{locator:{text}}`; bounded selectors are also supported. Upload takes host-authorized `{file:{name,mimeType,data}}`, with base64 bytes and no filesystem paths. Unsolicited downloads are cancelled. Screenshots are base64 PNGs; the host owns persistence and access policies. Remote viewers should poll bounded screenshots only while connected, dispatch pointer/keyboard input via their authenticated host, and enforce exclusive control there.

The internal HTTP/CONNECT egress proxy resolves every new destination, rejects any nonpublic DNS answer unless explicitly excepted, then connects to the approved IP. This pins connections against DNS rebinding and covers redirects/subresources/TLS tunnels. Chromium disables QUIC, nonproxied WebRTC and proxy loopback bypass. Service workers and unsolicited downloads are disabled. For hostile multiuser deployments, use one isolated worker/container per trust boundary plus OS network and filesystem restrictions; Chromium processes alone do not isolate worker-owned filesystem data. Browser tabs, action timeouts, viewport, uploads and session counts are bounded. CPU, memory, filesystem quota and outbound firewall policy belong to deployment limits.

Profiles are opaque IDs under the configured root, created with private permissions; never point the root at everyday Chrome data. The root contains credential-bearing browser storage: restrict its mount, encrypt the volume, and back up only while leases are released. Restart restores profile state into new sessions, not in-flight tabs/actions. Same-host dead PID leases are reconciled at acquisition. Other stale/shared-host leases require operator reconciliation after confirming no process owns them.

Run `bun test packages/subpolar-browser` for network/auth tests and controlled real Chromium interaction/persistence tests.
